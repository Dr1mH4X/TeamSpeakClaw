# Agent Note: 模块明细按子系统分页，架构文档只做索引

Status: implemented

## Problem

架构文档同时承担两件事：给人系统拓扑，也给改代码的人模块契约。两者对详略的要求相反——拓扑要短、子系统契约要全——于是它要么膨胀成模块参考（把常量、函数级序列和多条不变量塞进长段落），要么对两者都不完整。把明细全部推给源码也不行：跨文件的契约、调用顺序和「违反会出事」的约束散落在不同文件里，源码能回答某一行做什么，回答不了这些约束之间的关系。

## Decision

`docs/subsystems/` 下每个子系统一篇，固定四节：职责、关键路径与序列、不变量、相关决策。归属跟着代码边界走，不跟着功能特性走；横跨多个子系统的行为写在拥有它的那篇里，其他地方只链接。取舍理由不进子系统页，链接到 `.agents/notes/`。

`docs/architecture.md` 只留分层规范、入口流、子系统索引表、「新行为放哪里」与组件图：它是索引与拓扑，不是模块参考。分层归属表见 [docs/AGENTS.md](../../../../docs/AGENTS.md)，子系统页的规则见 [docs/subsystems/AGENTS.md](../../../../docs/subsystems/AGENTS.md)。

## Alternatives considered

- **继续把明细放在架构文档里**：文档要么持续膨胀，要么为了可读而不断删掉契约；两种结果都让改代码的人去翻源码，等于没有归属地。
- **明细只留在源码**：跨文件的契约与不变量没有陈述位置，评审时无从对照；同一约束会在多处注释里各写一遍。
- **每个模块一个 README**：本仓库是单二进制 crate，模块树由 `mod` 声明决定，README 会跟着模块重构漂移；而且 Rust 的模块文档已经由源码注释承担，再抄一层没有增量。
- **用 rustdoc / 源码注释承载**：适合描述单个类型或函数，不适合表达跨模块的调用顺序与全局不变量，也无法在 PR 里作为独立文稿评审。

## Consequences

新增或拆分一个子系统时，必须同步 `docs/architecture.md` 的索引表；索引与目录不一致视为文档缺陷。每篇子系统页的四节固定，`docs/subsystems/AGENTS.md` 是唯一格式归属地。

子系统页与源码同结构对应（入口文件写在每篇导语里），改代码时能直接找到对应页；反之，页里出现只属于源码的逐行细节就是越界。

没有自动门禁：仓库没有 Markdown 校验脚本，链接与索引一致性靠评审和人工核查。
