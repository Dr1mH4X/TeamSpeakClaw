# 模型可见能力的设计准则

本技能只放判据，没有外部来源：工具定义在 `src/tools.rs` 与 `src/tools/`，system 提示词段落是 `src/prompt/` 的源码常量，两者的归属说明分别在 [工具系统与权限门](../../../docs/subsystems/tools.md) 与 [模型可见提示词装配](../../../docs/subsystems/prompt.md)，这里不重述。

## 工作流步骤

通用原则：

- **先给最小上下文**：先暴露用途、可做的动作与约束，详细说明按需再装载。
- **让发现变明确**：每一个延后装载的资源都要有清楚的描述和可靠的取回方式。
- **关键约束保持可见**：权限、破坏性影响与必需的校验出现在相关动作之前，而不是藏在结果里。
- **输出有界**：返回简短结果加标识或路径，靠它取详情；不要倾倒整份日志或文档。
- **利用局部性**：在结果的旁边带上少量大概率需要的邻近上下文，例如发出一条回复时附上前面几条消息；省略与截断要显式标注，并给出取回更多的方式。
- **算总账**：省下的上下文只有在不引发更多搜索、重复读取或错误时才算收益。

工具定义：

- **删掉显然的约束**：模型能从调用结果学到的规则不必写，例如读一个不存在的文件会失败。
- **描述行为，不描述实现**：写清楚工具做什么、返回什么；内部机制、模型会在结果里看到的输出标记、以及执行细节都不写。
- **参数规则写在参数上**：默认值、取值范围、配对关系、何时该设置，属于那个参数的描述或 schema；如果一段描述随配置变化，通常说明变化的那部分属于参数。
- **每件事只说一遍**：工具定义不要在自己的提示词段落里重复，参数描述不要在工具描述里重复，一个工具的规则不要写进另一个工具。
- **量一下改动**：改前后对比首轮提示词的 token 数。

## 验证命令

```sh
cargo test --all-targets --locked
cargo clippy --all-targets --locked -- -D warnings
```

首轮 token 对比：改动前后各跑一次真实对话（或最小驱动的回合），记录 `src/prompt/` 装配出的 system 提示词长度。

## 报告要求

说明改了哪个工具定义或哪一段提示词、模型可观察的差异是什么、首轮 token 的前后变化；无法量化时明确说未测量。
