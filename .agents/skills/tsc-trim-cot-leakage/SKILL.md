# 清理思维链泄漏

思维链泄漏是站在书写会话视角、而不是站在仓库视角的文字：它引用只有那个会话看得到的东西，叙述「改了什么」而不是陈述「现在是什么」，或者在对一位已经离开的评审者说话。修法不是一律删除：段落里承载事实的从句要改写成像在 HEAD 上独立成立的样子，再删掉周围的叙述；一个事实都不承载的段落（审计代号、控制流叙述）直接删。

**前置背景**：[docs/AGENTS.md](../../../docs/AGENTS.md) 的精简版 slop checklist 拥有「叙述历史」与「CoT 泄漏」两条判据，本技能是它们的执行细则。这是判据，不是脚本。

## Sources of truth

- [docs/AGENTS.md](../../../docs/AGENTS.md)：写作规则与 slop checklist，本技能的上位归属。
- [.agents/notes/README.md](../../notes/README.md)：笔记的写作规则与核查清单。
- 被审范围内的源码注释、`docs/`、`.agents/notes/`、`website/`。

## 一条判据

对每段可疑文字问：**一个在 HEAD 上、看不到任何会话记录、PR 讨论或未提交草稿的读者，能不能解析每一个引用、验证每一句断言？** 不能，就把仍然成立的事实改写成仓库视角的表述、其余删掉；能，就不是泄漏，哪怕它读起来很历史——但可解析只是过了本技能这一关，在陈述当前状态的文档（README、`docs/`、代码注释）里，可解析的变更叙事仍然属于「叙述历史」，要按第 3 类处理。

## 分类

1. **会话内的决策引用** — `(decision 7)`、`(audit C2)`、`设计稿 §4.7`、`plan §1.4`、阶段编号（`T4`、`W3`、`P-I`）、「设计台账」。决策已有提交内的归属就按名字与路径引用它，否则删掉引用并把事实从句改写为独立成立。
2. **PR 与分支视角** — 「本 PR 增加」「上一条提交」「这一栈里的后续 PR」。改成已交付的机制或扩展点；延后的工作移进 `TODO` 或 issue 引用。
3. **变更叙事与版本戳** — 「之前」「现在」「不再」「旧的 X」，以及 `v1`、`这一版`、`本轮` 这类指代性时间戳。改成陈述当前行为；已修复的回归写成现在时的反事实（「没有 X 时会出现 Y」），不写仓库历史（「以前会 Y」）。
4. **评审编排** — 「评审意见是」「评审者确认过」「本笔记第 5 稿」「第二轮」。只留决策与依据本身，删掉是谁在什么时候说的。
5. **对评审者辩解** — 「这个转换是安全的，因为它只是……」「这样写是对的，因为……」。注释在向评审者自证，而不是向维护者陈述。写出使代码安全的不变量，或者删掉注释。
6. **复述与推导过程** — 控制流叙述（「先做 X，再做 Y」）、测试走查、显然分支的证明。删掉，只保留不显然的契约或不变量。
7. **对冲与规划残留** — 「目前应该够用」「先这样，大概率没问题」。升级为 `TODO`/`FIXME`，或改写成真实的边界值；删掉对冲。
8. **书写语言残留** — 中文文档里夹着的英文工作语言片段（`---- private ----` 分隔符、未翻译的整句），或英文文档里夹着的未翻译中文。翻译或删除。

## 不算泄漏

- **issue 与 PR 引用** — `#147`、`TODO(名字):`、「后续由 issue #N 负责」在 HEAD 上可解析，任何表面都保留。
- **Agent Note 与复盘里的已合并 PR 引用** — 那是被认可的变更史证据。
- **抑制告警的理由** — `#[allow(...)]` 与 clippy 豁免后面的原因、覆盖豁免说明是被要求写的文字；理由错了就改对，不删。
- **反事实现在时的回归钉** — 「没有 X 时会出现 Y」「朴素的 X 会……」，这是测试与注释里的现在时表述。
- **实测边界** — 「实测 512 层嵌套约 0.15s」这类校准常量的证据，「实测」二字是承重的。
- **运行期的旧/新状态** — 「旧连接排空后新连接才接受」是运行期生命周期，不是变更史。
- **笔记变更故事段落里的历史阶段名** — implemented 笔记的 `## Problem` 里描述「修复前的形态」是被允许的体裁；但指代性时间戳（「本轮」「这一版」）在笔记正文里同样不用。
- **可按设计在仓库外解析的外部引用** — 标准条款（RFC 9110 §10.1.5）、上游项目文档。
- **提案笔记内部自己的条目编号** — proposed 笔记里 `O1`/`O2a` 这类编号是同一篇内部可解析的提案项标识，属于体裁，保留。
- **项目自称** — 用「本项目」「仓库」作主语不算视角泄漏。

## 工作流步骤

1. 先划定范围并明确排除项：不改 `.agents/notes/archived/`，不改 `website/i18n/` 的英文镜像（它跟着中文源文改），不改 `target/` 与生成产物。
2. 只读审计：先用下面的探针命令找候选，每个探针先用一个已知正例和一个近似反例校准，再逐条按语义判断。探针只是找候选，不是定义；还要无差别地读范围内文字最密的几处（模块顶部注释、`docs/` 各篇、活跃笔记）。
3. 按归属地修：规则性文字改 `docs/AGENTS.md` 的归属篇；笔记改对应笔记；代码注释改源码；模型可见文案属于行为，除非有行为证据否则不动，改为报告里记一笔。
4. 删任何东西之前，先把段落里的事实逐条列出来，检查是否会把义务改成背书、把假设说成已交付、删掉真事实、或丢掉证据来源。
5. 验证：重跑探针，剩下的命中应只有被认可保留的；确认每一条残留引用在 HEAD 上能解析；文档改动按 [docs/AGENTS.md](../../../docs/AGENTS.md) 复核。

## 验证命令

```sh
# 会话内编号与阶段标签
grep -rnE "\((decision|ruling|audit) ?[0-9A-Z]|设计稿 ?§|plan ?§|（[A-Z][0-9]+）" docs/ src/ .agents/notes/ --include="*.md" --include="*.rs"

# 变更叙事与指代性时间戳
grep -rnE "之前|不再|曾经|本轮|本批|这一版|第 ?[0-9]+ ?稿|目前应该|大概率" docs/ src/ .agents/notes/ --include="*.md" --include="*.rs"

# 评审视角
grep -rnE "评审|reviewer|这条建议|按审查意见" docs/ src/ .agents/notes/ --include="*.md" --include="*.rs"
```

## 报告要求

给出：范围、每条探针的命中数、逐条判定（保留/改写/删除）及一句理由、被删段落里事实的落地位置，以及任何因缺行为证据而延后处理的模型可见文案。
