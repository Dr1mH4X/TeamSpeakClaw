# 0.6.3 (2026-10-16): 语音回合顺序与失败说明

这一版把语音与文本回合的顺序、取消和资源占用收进一套准入与排队规则，模型调用失败与提示词装配失败都会把原因作为文本发给用户，提示词由代码内的段落装配。

## 修复

- 同一会话的回合按到达顺序串行执行，语音与文本混用时的回复顺序与实际发言一致（#95）。
- 被忽略的消息在进入容量队列前丢弃，全局并发名额留给真正要执行的回合（#95）。
- 语音回合被抢占或打断时立刻释放并发名额、会话锁与语音链路名额，排在后面的回合同样可以被打断（#101）。
- TTS 与工具调用的收尾走协作式取消，回合被打断时不会停在句间 30 秒的空转上（#100）。
- TS 会话历史以解析出的调用者 UID 为键，客户端 ID 被复用时新客户端不会读到上一位的历史（#101）。
- 唤醒判定与帧状态并入唤醒门的 speaker 会话，检测到但尚未收音的语音最后才被容量淘汰（#101）。
- STT 与 TTS 的响应体各有体积上限（64 KiB 与 8 MiB），语音链路的在途名额固定为 8 个（#100）。
- 上下文超限的重试可以安全取消，被取消的回合把收缩掉的历史放回，音频 base64 缓存只在单次请求内存在（#102）。
- 模型调用失败按类别路由，体积类拒绝、上下文窗口类拒绝与空完成都把失败原因作为文本发给用户（#105）。
- 提示词装配失败也给用户一句失败说明，而不是只留一行日志（#98）。

## 优化

- 提示词由 `src/prompt/` 的有序段落装配，变量在装配期严格解析、空段落自动省略，`config/prompts.toml` 与 prompts 配置随之移除（#98）。
- 代码与文档里的 skill 词汇统一为 tool，`acl.toml` 的 `allowed_skills` 更名为 `allowed_tools`，旧键仍可解析（#98）。
- 会话生命周期收敛到 `adapter/lifecycle.rs`，推测性的会话阶段与日志模板删除，订阅耗尽保持静默（#97）。
- 唤醒门的 speaker 会话是 clid 状态的唯一归属，路由器只读这一份（#96）。
- 路由器拆出回合骨架 `router/turn.rs`，语音轮次的归属独立成模块（#94）。

## 其他

- 决策记录移到 `.agents/notes/` 的生命周期分树，`.agents/skills/` 入库并写明技能规范，每个版本的 Release 正文是仓库文件 `docs/release/<tag>.md`（#103）。
- Release 标题取正文首行，形如 `0.6.3 (2026-10-16): 语音回合顺序与失败说明`，分节固定为新增、修复、优化、其他四类。
- 网站文档补充 FunASR 与 whisper 的本地 STT 安装说明，配置页移除提示词一节。
- 网站依赖与 Rust 依赖升到公告已修复的版本，其中 rustls 到 0.23.46，pnpm 与 npm 两份 lock 重新生成（#104）。

## 升级注意

- 提示词配置从配置面移除：system 提示词、运行期上下文与 TTS 风格提示是代码内常量，config 目录里的 `prompts.toml` 没有作用，可以删掉（#98）。
