# AGENTS.md — 子系统文档

本目录每个文件对应一个子系统，是模块级明细的归属地：架构文档只做索引，源码不适合承载的跨文件契约、关键序列与不变量写在这里。

## 归属边界

一个子系统是一块有明确契约的代码（适配器、路由、引擎、语音、工具、配置）；划分跟着代码归属走，不跟着功能特性走。横跨多个子系统的行为写在拥有它的那个子系统里，其他地方只链接。

写作规则继承 [../AGENTS.md](../AGENTS.md)：只写当前状态与契约，不写变更史、不写 PR 与 commit 编号、禁 emoji、一段一物理行。另外三条界限：

- 不誊写源码里能直接读到的实现细节（逐行逻辑、私有函数、常量表），也不写决策的理由与取舍——后者的归属地是 `.agents/notes/`，每篇末尾用「相关决策」链过去。
- 不复述用户可见的配置说明与操作步骤（归 `website/`），也不复述目录级规则（归该目录的 `AGENTS.md`）。
- 每篇固定四节且按序：职责、关键路径与序列、不变量、相关决策；没有相关决策记录时整节省略，不要写「无」。

## 新增与拆分

新增一篇的条件是那块代码有独立契约、且在 [../architecture.md](../architecture.md) 的索引里占一行。一篇文件同时讲了两件不相关的事就是拆分信号：按契约边界拆开，同步更新索引表，并让旧位置留下指向新文件的链接。
